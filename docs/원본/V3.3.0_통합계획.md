# 생각의 연결 v3.3.0 — 통합 계획 (기존 삭제·덮어쓰기 없음)

기준일: 2026-10-31
기반: v3.0.0 패키지 + v3.3.0 증분 업데이트 (README_FIRST, CHANGELOG, UPDATE_REQUIREMENTS)
이번에 새로 만든 파일: `V3.3.0_문체시안.md` (승인 대기), 이 파일 `V3.3.0_통합계획.md`
보존 확인: v3.0.0 원본 ZIP, 추출본, 이미지 9장, 데모 3개, P0 프로토타입 `thought_connection_v3_p0.html`, P0 설계·테스트 기록 — 어느 것도 삭제하거나 덮어쓰지 않음. v3.3.0 문서는 별도 폴더 `v3.3.0_update/`에 원본 그대로 보관함.

## 1. 충돌 검사 — v3.0과 v3.3.0은 충돌하지 않음
- 5대 카테고리 순서 유지: 좋은 질문 → 기존 신호 → 신호 전환 → 습관 개조 → 원하는 삶 = 자유
- 모바일 세로, 최소 글, 추상 시냅스, 코랄 기존 / 청록 새 연결, 뇌 그림 금지 — 유지
- 책·웹·iOS·Android 동일 콘텐츠 ID 체계 — 유지, 아래 4절에서 확장만 함
- 술 대표 콘텐츠 + 안전 문구 + 『술의 배신』 인용·복제 금지 — 유지
- 개인 기록 비공개 기본값, 로컬 저장, JSON 백업, 삭제 — 유지
- 달라지는 것은 추가 기능과 문체뿐임. 기존 기능을 지우는 변경은 없음.

## 2. v3.1 — 사용자가 앱을 함께 만든다 (설계)
- 기본값은 비공개. 공유는 별도 명시적 동의 + 공개 범위 선택 + 민감 정보 확인·삭제 기회 이후에만.
- 공유하지 않아도 개인 연결망 기능은 전부 쓸 수 있음.
- 추가할 동작: 질문 제안, 기존 신호 기록, 여러 해석 가지 연결, 실험·결과 기록 (도움이 안 된 이유 포함), 기능 제안, 중복 병합 제안, 오류 신고, 개선 투표 (P2로 미룸, 아래 참조), 운영자 검토, 반영/보류/기각 사유와 변경 이력 공개.
- UX 흐름: 내 기록 → 공유하기 (동의 화면) → 검토 중 → 공개 후보 / 보류 (사유 표시). 공유한 기록만 공동 지식 후보로 보임.

## 3. v3.2 — 경험을 모아 검토 가능한 논리로 만든다
- 지식 카드 한 장에 모을 항목: 질문 / 기존 연결 / 새 해석 후보 / 경험 보고 (익명, 조건, 시도, 느낀 변화) / 자유·행복 신호 (자율성, 평온, 만족, 부담감 — 자기보고, 1~5점은 선택 사항이며 과학적 점수가 아님) / supporting evidence (출처 있는 자료, 검토일) / 반례 / 적용 조건·한계·안전 경고 / 잠정적 종합 (단정 금지) / 수정 이력.
- 지식 카드 상태: 제안됨 → 검토 중 → 공개 (근거 수준 표시) → 수정됨 / 보류.
- 원칙: 경험담이 많다고 과학적 인과관계로 승격하지 않음. 출처 없는 주장은 "사용자 경험 / 가설"로 구분. 상반된 경험이 있으면 성공 사례만 보여주지 않고 반례와 조건을 함께 보여줌.
- 술 흐름 예시 (v3.0에서 확장): 질문 "술이 정말 스트레스를 풀어주는 걸까?" → 기존 연결 스트레스 → 술이 필요하다는 생각 → 마시기 → 새 해석 "잠시 기분이 달라지는 것과 문제가 해결되는 건 다를 수 있다" → 선택 쉬기·산책·대화 → 기록 다음 날 컨디션·만족감·선택의 자유·예상과 달랐던 점 → 공동 지식에 도움이 된 조건 / 그렇지 않았던 경우 / 관련 근거를 함께 제시. 갈망·감정 자체를 "가짜"라고 부르지 않음. 의존·금단 위험 시 갑작스런 금주를 일반 권고하지 않음.

## 4. 데이터 모델 증분 (기존 v3.0 모델에 추가만 함, 마이그레이션 전 충돌 검토 필요)
- `Contribution(id, author_id, type, parent_id, body, visibility, consent_id, status, created_at)`
- `ExperienceOutcome(id, experience_id, context, autonomy_note, calm_note, satisfaction_note, negative_outcome_note, self_rating_optional)`
- `EvidenceItem(id, knowledge_claim_id, evidence_type, source_uri, summary, reviewed_at)`
- `KnowledgeClaim(id, question_id, proposition, status, confidence_label, limitations, updated_at)`
- `Counterexample(id, knowledge_claim_id, experience_or_source_id, note)`
- `KnowledgeRevision(id, knowledge_claim_id, previous_version, new_version, reviewer_id, rationale, created_at)`
- `FeatureProposal(id, author_id, description, status, vote_count, resolution_note)`
- `EditorialStyleGuide(id, version, locale, approved_by_user_at, rules)`
- 콘텐츠 ID 확장: 기존 `TC-{부}-{장}-{종류}{번호}` 유지. 지식 카드는 `TC-KC-{주제번호}`, 기여는 `TC-CT-{번호}`로 별도 구분해 책 ID와 섞지 않음.
- 공개 기여와 개인 기록은 논리적으로 분리. 삭제·동의 철회 시 공개 후보에서도 재처리 경로 마련 (다음 단계 설계).

## 5. 우선순위 (업데이트 문서 기준, 현실 일정으로 정리)
- P0 (이미 P0 프로토타입에 있음, 유지): 개인 질문/해석/경험 기록, 자유·행복 신호 기록, 5대 카테고리, 시냅스 UI, 독서·일기·명상, 기본 프라이버시, 책-앱 연결.
- P1 (초기 베타 권장, 다음 구현): 선택적 질문/해석 공유, 경험 제안, 운영자 검토, 출처·반례·적용 조건을 보여주는 지식 카드, 콘텐츠 버전/수정 이력.
- P2 (미룸): 공동 개선 투표, 추천 고도화, 커뮤니티 피드, 대규모 통계/개인화. 운영·안전 역량 없이 공개 커뮤니티를 무리하게 열지 않음.
- 문체: 시안 승인 후에만 전체 적용 (P1과 병행 가능, 단독으로 먼저 적용해도 됨).

## 6. 화면 흐름 변경 (시안 단계, 구현 전)
- 기존 5개 탭 유지 + 각 탭에 "공유하기"는 별도 동의 화면으로 분리 (탭 안에 바로 공개 버튼을 두지 않음).
- 지식 카드 화면 (신규, P1): 질문 → 기존 연결 → 새 해석 → 경험 (조건별) → 반례 → 잠정 종합 → 수정 이력, 근거 수준 표시.
- 기여 화면 (신규, P1): 내 제안 목록, 상태 (제안됨/검토 중/공개/보류), 보류 사유.
- 문체 교체 화면 (승인 후): 이전 문구와 새 문구를 나란히 보여주고 되돌리기 버튼 유지.

## 10. 위험 요인
- 공개 커뮤니티를 서두르면 안전·운영 부담이 커진다. P1은 검토 있는 지식 카드까지만, P2 투표·피드는 역량 확보 후.
- 경험담을 근거로 오인할 위험: 지식 카드에 근거 수준 표시를 빠뜨리지 않는다.
- 문체를 바꾸다 건강 정보가 느슨해질 위험: 안전 문구와 근거 구분은 문체와 별도로 고정한다.
- Threads 조사 한계: 공개 검색으로 패턴을 봤을 뿐, 특정 작가·게시물을 대표 사례로 삼지 않았다. 문체는 패턴에서 가져오고, 표현은 새로 썼다.
