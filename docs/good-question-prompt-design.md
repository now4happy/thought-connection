## 1. 파트 구성 (사용자 결정 2026-11-01 13:27, 이전 구성을 대체한다)

- **1파트 좋은질문**: 역질문을 통해서 유저의 근본 질문(신호)를 찾는 파트이다. = 5단계 1단계.
- **2파트 신호**: 신호와의 분리(근본 질문이 나와 다르다는 것을 인식한다) + 신호의 전환(다르다는 것을 인식한 후 그 신호를 긍정적으로 전환한다). = 5단계 2단계 기존 신호 + 3단계 신호 전환.
- **3파트 자유**: 습관개조 + 원하는 삶. = 5단계 4단계 습관 개조 + 5단계 원하는 삶 = 자유.
- 파트는 작업 단위이고, 5단계는 맵의 순서이다. 둘을 섞어 쓰지 않는다.

## 2. 원본 프롬프트 요약 — 좋은 질문 파트에 해당하는 부분

### 역할과 대화 원칙 (좋은 질문 파트의 기본)
- 역할: '내면 명탐정'. 사용자의 심리·습관·성격 고민을 사건처럼 탐색하며, 사실·감정·해석·욕구·행동 사이의 연결을 사용자가 스스로 발견하도록 돕는다. 빠른 해결보다 깊은 이해를 우선한다.
- 진단·낙인·비난·훈계하지 않는다.
- 답변을 받으면 짧게 공감하고 1~2문장으로 반영한 다음 중요한 질문 하나만 한다.
- 질문은 구체적인 경험을 중심으로 한다. 답을 강요하지 않으며, 추측은 반드시 '가설'로 표시하고 확인받는다.
- 같은 내용을 표현만 바꿔 반복 질문하지 않는다. 사용자가 원하면 언제든 정리하거나 중단한다.
- 충분한 탐색 전에는 해결책을 서두르지 않는다. 전문적 지원이 필요하면 솔직히 안내한다.
- 사용자 표현과 감정의 깊이에 맞춰 공감하며 과장된 위로나 이모지를 피한다.

### 탐색 단계와 좋은 질문 파트의 대응
| 원본 탐색 단계 | 좋은 질문 파트에서의 자리 |
|---|---|
| 1. 사건 접수: 고민을 한 문장으로 요약하고 '내가 이해한 게 맞아?'라고 묻는다 | 질문 입력 단계. 생각의 연결의 확정 문구와는 별개로, 원본의 접수 문구이다 |
| 2. 단서 수집: 상황 → 생각 → 감정/몸의 반응 → 행동 → 결과를 하나씩 확인한다 | 역질문 탐색 단계 |
| 3. 패턴 탐색: 반복, 예외, 보호 기능, 피하고 싶은 감정을 살핀다 | 역질문 탐색 단계 |
| 4. 중간 수사 보고: 보통 5~7회 의미 있는 질문 후, 또는 중요한 연결 발견·질문 반복·사용자 요청 시 질문을 멈추고 요약한다. 사건의 시작, 생각의 흐름, 반복되는 마음, 확인된 연결, 아직 남은 단서를 보여준다. 미확인 요소를 지어내지 않는다 | '여기서 정리' 단계에 해당한다. 5~7회는 중간 보고 시점의 참고 기준이며, 강제 횟수가 아니다 |
| 5. 선택: '아직 더 살펴볼 마음이 남아 있어' 또는 '오늘의 핵심에 가까워진 것 같아' 중 사용자가 방향을 정하도록 한다. 자유 응답도 허용한다 | 계속 탐색할지, 정리로 갈지 사용자가 정한다 |
| 6. 추가 탐색: 기존 답을 다시 묻지 않고 2~4회 새 단서를 탐색한 후 필요하면 보충 보고한다 | 추가 역질문 단계. 횟수는 참고 기준이며 강제하지 않는다 |
| 7. 근본 질문: 사용자의 언어로 핵심 질문 하나를 제시하고 단서 2~3개로 이유를 설명한다. 확정된 진단이나 정답으로 제시하지 않는다. 질문이 맞는지 확인한다 | '지금 내 질문' 후보 제시 및 확인 단계. 사용자가 수정·확정해야 한다 |
| 8. 가설 검증: 필요시 2~3개의 가설을 근거와 함께 제시하고 사용자가 판단한다 | 좋은 질문 파트를 넘어서는 부분이다. 신호와의 분리·전환 파트나 5단계의 신호 전환과 연결될 수 있어, 파트 배치는 사용자 결정이 필요하다 |
| 9. 작은 실험: 사용자가 원할 때만 부담 없는 행동 실험 하나를 제안한다. 일기·횟수·기록을 강요하지 않는다 | 습관 개조(5단계 4단계)에 가깝다. 좋은 질문 파트의 본분이 아니다 |
| 10. 사건 정리: 사건 개요, 확인된 단서, 생각-감정 연결, 유력 가설(선택), 오늘의 근본 질문, 남은 단서(선택), 작은 실험(선택)을 정리한다 | 정리 화면. 5단계 맵으로 연결되는 지점이다 |

### 최종 목표 (원본)
- 질문을 끝없이 이어가는 것이 아니라, 적절한 순간에 생각의 지도를 펼쳐 보여주고 사용자가 스스로 가장 중요한 질문을 발견하도록 돕는다. 음악과 이미지는 그 과정을 조용히 뒷받침한다.

### 다국어 설계
- 기본 locale: ko-KR. 향후 en-US, ja-JP, zh-TW 등 추가.
- 모든 UI 문구, 버튼, 상태 메시지, 접근성 텍스트는 locale 리소스에서 가져온다. 코드에 한국어 문자열을 고정하지 않는다.
- 질문의 목적과 공감의 강도는 유지하되 문화적 맥락, 존댓말, 길이, 비유는 현지화한다.

- 생각의 연결의 i18n 카탈로그(ko/en)와 방향이 맞는다. 단, 카탈로그 방식과 locale 리소스 방식 중 어느 것을 쓸지는 구현 시 정한다.

### 답변 생성 중 음악·이미지 (v2.4 신규, 웹 설계)
- 목적: 답변 생성 중 빈 화면이나 단조로운 스피너 대신, 대화의 정서적 분위기를 은유적으로 표현하는 정적인 이미지 또는 부드러운 장면 전환과 선택형 배경 음악을 제공한다. 이는 심리 분석 결과나 감정 판정이 아니다.
- UI 상태: idle(기본 배경, 음악 기본 정지) / thinking(준비된 장면 이미지 표시, '생각을 연결하는 중' 같은 짧은 문구 표시, 음악은 사용자가 켠 경우에만 재생) / responding(텍스트가 도착하면 즉시 읽을 수 있게 보여주고, 시각 효과는 방해하지 않도록 축소) / summary(중간 수사 보고의 생각 흐름을 카드나 연결도로 표현) / root_question(오늘의 근본 질문을 강조하되 과장된 연출을 피함) / error·offline(생성 실패 시 정지 화면 대신 재시도 안내와 기존 대화 보존).
- 이미지 정책: 초기에는 앱에 포함된 최적화된 이미지·애니메이션 자산을 사용해 응답 지연 없이 표시한다. 장면 예시: 조용한 서재, 별이 있는 밤하늘, 호숫가, 숲길, 따뜻한 창가. 페르소나별 이미지 테마를 독립 설정한다. 대화 내용을 기반으로 실시간 이미지 생성하는 기능은 미래의 선택 기능으로 분리한다. 사용자의 심리 상태를 이미지로 진단하거나 확정하지 않는다. 충격적·자극적인 이미지와 강한 깜빡임을 피한다. reduced-motion 설정, 저사양 기기, 데이터 절약 모드를 지원한다. 이미지 끄기와 대체 텍스트를 제공한다.
- 음악 정책: 기본값은 무음(자동재생 금지). 명시적인 재생 조작 후에만 재생한다. 저작권과 라이선스가 확인된 오리지널·적법하게 사용 가능한 음원만 제공한다. 분위기 예시: 잔잔한 피아노, 앰비언트, 자연 소리. 감정을 단정해 특정 음악을 강제하지 않는다. 재생·일시정지, 음량, 음소거, 음악 끄기, 설정 기억 기능을 제공한다. 답변 도착 시 음악을 갑자기 끊지 않고 설정에 따라 서서히 줄이거나 유지한다. 브라우저·운영체제의 자동재생 정책을 준수하고, 통화·스크린리더·다른 오디오와 충돌을 최소화한다.
- 동기화·성능: 텍스트 응답은 이미지·음악 준비를 기다리지 않는다. 멀티미디어는 별도 비동기 작업으로 처리한다. 이미지는 사전 로딩·캐시, 음악은 짧은 루프 및 페이드 인·아웃을 지원한다. 생성 시간이 길어도 진행률 퍼센트를 임의로 꾸미지 않는다. 감정 분석을 통해 사용자에게 특정 심리 상태를 단정하거나 민감한 데이터를 외부 음악·이미지 제공자에게 전달하지 않는다. 서버의 대화 상태와 클라이언트의 표현 상태를 분리한다.
- 경계: ChatGPT 텍스트 프롬프트만으로 음악 재생이나 생성 중 이미지 애니메이션을 실행할 수는 없다. 실제 구현은 클라이언트 코드, 자산, 적절한 라이선스 및 사용자 설정이 필요하다.

## 4. 충돌·미승인 항목 — 원본을 그대로 적용하지 않는다

- **페르소나 이름**: 원본의 '내면 명탐정'은 이 프롬프트의 페르소나 이름이다. 생각의 연결이라는 프로젝트 이름을 바꾸는 것이 아니다. 좋은 질문 파트에서 이 페르소나를 쓸지는 사용자 결정이 필요하다.
- **미래 페르소나 목록**: buddha_inspired, jesus_inspired, grandmother_warm, celebrity_inspired 등은 원본의 제안일 뿐, 생각의 연결에서 승인된 것이 아니다. 역사적·실존 인물의 실제 발언이나 정체성으로 오인시키지 않고, 허구적 또는 영감 기반 스타일임을 알린다는 원본의 안전 규칙은 그대로 유지한다.
- **첫 응답 문구**: 원본의 '🌱 오늘은 어떤 마음의 사건을 함께 살펴볼까요?'는 생각의 연결의 승인 문구가 아니다. 승인 문구는 앱 첫 화면 C안, 질문 입력 '지금 고민이 뭐야?', 탐색 시작 A안이다. 첫 응답 문구를 바꾸려면 사용자 승인이 필요하다.
- **중간 보고 시점 5~7회, 추가 탐색 2~4회**: 참고 기준일 뿐 강제 횟수가 아니다. 생각의 연결의 규칙(질문 횟수 강제 금지, 1~2턴 후에도 바로 답 듣기·정리·중단 가능)이 위에 적용된다.
- **음악·이미지 구현**: 웹 설계 명세일 뿐, 생각의 연결 프로토타입에 아직 구현되지 않았다. 라이선스 확인, 자동재생 금지, 무음 기본값, reduced-motion, 대체 텍스트는 구현 시 그대로 지켜야 한다.
- **용어**: 원본의 '근본 질문'은 생각의 연결의 '근원 질문'·'지금 내 질문' 후보와 같은 자리이다. 용어를 섞어 쓰지 않고, 생각의 연결에서는 사용자가 수정·확정한 질문만 근원 질문이 된다는 규칙이 위에 적용된다. "자기 암시 쇄뇌"는 쓰지 않고 "신호 전환반복"을 쓴다는 용어 규칙도 그대로 적용된다.
- **파트와 5단계의 구분**: 원본의 탐색 단계 8~10(가설 검증, 작은 실험, 사건 정리)은 좋은 질문 파트만의 내용이 아니다. 신호와의 분리 파트, 신호의 전환 파트, 5단계의 신호 전환·습관 개조 중 어디에 둘지는 사용자 결정이 필요하다.

## 5. 버전 분리 — 설계 시 참조 (사용자 결정 2026-11-01 13:42)

- 유아~중학생: 교육 버전. 중학생 이후(고등학생~성인): 일반 버전. 지금 만들고 있는 것은 일반 버전이다.
- 교육 버전: 좋은 질문은 더 단순화하고, 결론은 도덕적으로 흐르게 한다. 좋은 질문 파트는 짧게 머물고, 신호 파트에서 트레이닝 과정을 길게 한다.
- 일반 버전: 치유가 들어가고, 자유도가 높다.
- 설계 함의: 좋은 질문 파트는 두 버전에서 같은 뿌리(역질문으로 근본 질문 찾기)를 쓰되, 질문의 깊이와 머무는 길이가 다르다. 신호 파트는 교육 버전에서 트레이닝 비중이 커진다. 결론 문구는 버전마다 방향이 다르다(교육 = 도덕적 흐름, 일반 = 치유와 자유).

- 받은 것: `inner_detective_web_v2_5_ripples.html` (단독 HTML, 12KB) + 패키지 zip. zip 안의 v2.4 md는 이전 원본과 해시가 일치해 프롬프트는 바뀌지 않았다. 바뀐 것은 웹 시안뿐이다.

## 6. 고정 사항 (이 정리와 무관하게 유지된다)

- 앱 첫 화면 C안, 질문 입력 '지금 고민이 뭐야?', 탐색 시작 A안은 변경하지 않는다.
- 5단계 순서: 좋은 질문 → 기존 신호 → 신호 전환 → 습관 개조(감정 조절·마인드 전환·행동 변화) → 원하는 삶 = 자유.
- 메타보기: 시작 50/100, 좋은 질문 하나마다 3씩 성장, 활동 횟수로는 오르지 않는다. 출석·연속 기록·일일 목표·순위 경쟁은 없다.
- 개인 대화 기본 비공개, 공동 공유는 별도 명시적 동의·익명화·철회 가능. 의료·상담 서비스가 아니며 진단·처방을 하지 않는다.
- 승인 전 기존 자료를 덮어쓰지 않고 버전별로 보존한다.
