## 1. 검토 결과 (질문별)

| 질문 | 확인한 사실 |
|---|---|
| `.stage`가 `height:100%`인데 괜찮은가 | **문제였다.** 부모 `#chat`(section)에 높이가 없어서 100%가 auto로 풀린다. 말풍선이 쌓일수록 화면 전체가 길어지고 입력창이 아래로 밀린다. 측정: 뷰포트 700px에서 stage 높이 3,712px, 입력창 아래끝 4,108~5,735px(긴 답 뒤). 이것이 증상 1(마지막 줄·입력창이 안 보임)의 직접 원인으로 보인다. body가 `overflow:hidden`이라 사용자가 끌어올 수도 없다 |
| 모바일 키보드 | `dvh`는 Android Chrome·iOS에서 키보드가 열려도 줄지 않는다(코드로 재현한 것이 아니라 브라우저 일반 동작으로 알려진 사실이며, **이 환경에서 실제 키보드로 확인하지 못했다**). 그래서 `visualViewport` 높이·offsetTop을 쓰고, 없으면 `100dvh`로 대체한다 |
| `scrollEnd()`가 `#center`만 건드린다 | 맞다. 말풍선 추가·스트리밍 조각·답 완료 때만 호출됐고, 창 크기·키보드·레이아웃이 바뀐 뒤에는 다시 내리지 않았다 |
| `field.typing()`을 입력마다 돌리나 | 입력마다 `quietUntil`만 갱신한다(가볍다). 문제는 그 1.2초가 지나면 **입력창에 커서가 있는 동안에도 초당 약 15번(실측 3초에 92번) 그린다**는 것이었다 |
| `grow()`가 글자마다 높이를 재나 | `field-sizing`을 지원하는 브라우저에서는 아니다(v3.3.12). 미지원 브라우저에서는 글자마다 `height='auto'`→`scrollHeight` 강제 레이아웃이었다 |
| 움직임 멈춤 상태 | 높이가 바뀔 때마다 `ResizeObserver`→`layout()`→`draw(0)`을 **동기로** 한 번 그렸다 |

## 2. 바꾼 것 (`app/v3.3.13/index.html`)

1. **화면 높이:** `.stage`를 `position:fixed`로 두고 `top:var(--vvt)`, `height:var(--vvh)`(`visualViewport`, 대체값 `100dvh`/`100vh`)로 잡는다. 키보드가 열렸을 때만 아래 안전 여백을 뺀다(`.kb` 클래스).
2. **스크롤:** `scrollEnd(force)`. 말풍선 추가·답 완료 때는 무조건 내리고, 스트리밍·화면 크기 변화 때는 "아래에 붙어 있을 때만" 내린다. `#log`·`#center`에 `ResizeObserver`를 걸어 레이아웃이 끝난 뒤에도 다시 내리고, 한 프레임 뒤 한 번 더 내린다. 입력창에 커서가 가면(키보드 열림) 250ms 뒤 내린다. 사용자가 직접 위로 올려 읽는 중이면(휠·터치·키 직후 800ms 안의 scroll) 스트리밍이 끌어내리지 않는다.
3. **키 반응:**
   - 입력창에 커서가 있으면 배경을 그리지 않는다(예외: 답을 기다리는 중이거나 파문이 살아 있을 때 초당 10번 이하).
   - `keydown`·`beforeinput`·`compositionstart/update`(한글 조합)에서도 쉼 시간을 갱신한다(1.2초→1.5초).
   - `navigator.scheduling.isInputPending()`이 참이면 그리지 않는다(지원하는 브라우저만).
   - 멈춤 상태의 다시 그리기는 잠잠해진 뒤(180ms) 한 번.
   - `grow()`(field-sizing 미지원 브라우저)는 프레임당 한 번.
4. 콘솔 라벨 `[TC v3.3.13]`, 머리말 주석.
