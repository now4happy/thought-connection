## 4. 확인한 방법

- **실제 Gemini 연결 점검은 하지 못했다.** 이 작업 환경에서는 Google 서버에 요청을 보낼 수 없다.
- 대신 로컬 Chromium에서 페이지의 **실제 Firebase 호출 코드**를 그대로 실행했다. `www.gstatic.com/firebasejs/13.0.0/`의 모듈 4개(app·auth·ai·app-check)만 가짜 모듈로 바꿔 끼웠고, 26개 항목이 **26/26 통과**했다. 점검 항목:
  - 로그인 흐름, App Check 초기화와 reCAPTCHA 키 전달
  - 첫 요청이 3.5 Flash-Lite로 감, `__TC_BACKEND`를 넣어도 쓰이지 않음
  - 한도 0이면 다음 모델로 넘어가 답이 나옴, 막힌 모델을 다음 보내기에서 건너뜀
  - 세 모델이 모두 막히면 3건만 쓰고 대기, 카운트다운이 끝나면 풀린 모델로 1건
  - '자세히'에 모델 3개·원인 이름·원문이 나오고 대화 내용은 없음, 대기 중에는 요청 0건
  - 모두 하루 한도이면 '오후 4:00' 표시, 새로고침 뒤에도 요청 0건
  - 모두 404이면 설정 안내, 다음 보내기도 0건
  - 403이면 다른 모델로 넘어가지 않음, 500이면 연결 실패 안내
  - 답 못 받은 글을 합쳐 보냄, 원인 정보 없는 429면 다음 모델
  - 스크립트 오류 0, 휴대폰 폭 가로 넘침 없음
- 태평양 자정 계산 5건(서머타임 시작·끝 포함)은 v3.3.10과 같은 결과다.
- 가짜 오류의 문장 형식은 Firebase JS SDK 13.0.0 원본(`request.ts`: `[상태] 메시지 + details JSON`)과 포럼·DEV 글에 보고된 Gemini 오류 문장을 따랐다. **Firebase 중계가 실제로 같은 형식으로 보내는지는 확인하지 못했다.**

## 6. 사용자가 확인할 곳 (1번 질문 답)

로그인은 Firebase를 만든 **같은 Google 계정**으로 한다. 화면 이름은 한국어 화면에서 조금 다를 수 있다.

1. **Google Cloud 콘솔**(가장 확실함)
   - `console.cloud.google.com` → 맨 위 프로젝트 선택에서 `thought-connection`
   - → 메뉴 **API 및 서비스(APIs & Services)** → **Gemini API**(다른 표시 이름: Generative Language API)
   - **측정항목(Metrics)** 탭: 응답 코드별 트래픽에서 429가 몇 건인지(Firebase AI Logic 모니터링 문서가 안내하는 곳)
   - **할당량 및 시스템 한도(Quotas & System Limits)** 탭: 모델별 한도 값과 사용량
   - 바로가기(콘솔 주소 규칙으로 만든 링크): `https://console.cloud.google.com/apis/api/generativelanguage.googleapis.com/metrics?project=thought-connection`
2. **AI Studio의 Rate limit 화면**
   - `aistudio.google.com/rate-limit` (Gemini API 문서가 안내하는 주소) → 위쪽 프로젝트 선택에서 `thought-connection`
   - 목록에 없으면 AI Studio로 프로젝트를 가져와야(import) 한다. 정확한 버튼 이름은 공식 문서에서 확인하지 못했다.
   - 화면에 "Project quota tier unavailable"이 보이면, 이것도 포럼에 따로 보고된 새 프로젝트 문제다.
3. **Firebase 콘솔**
   - `thought-connection` → **AI Services → AI Logic → AI monitoring** 탭(꺼져 있으면 Settings 탭에서 켬)

**판단 기준:** 사용량이 **0인데 429**가 나면 2절의 포럼 사례와 같은 경우다.
