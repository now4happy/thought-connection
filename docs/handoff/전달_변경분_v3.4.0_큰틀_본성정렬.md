## 7. 바뀐 곳 (= 제안 내용)

### 7-A. 본성에 거스르는 지점 12곳 (근거 → 제안)

표기: **[근거]** 어느 문서·코드에서 확인했는지 · **[본성]** 왜 거스르는지 · **[제안]** 거스르지 않는 방향

#### ① 써보기 전에 회원가입부터 해야 한다
- [근거] index.html: 로그인하지 않으면 대화 불가(`needLogin`). 가입 칸 = 이름·이메일·비밀번호·비밀번호 확인·동의 체크 5개.
- [본성] 사람은 가치를 먼저 맛본 뒤에 약속한다. 무엇을 얻을지 모르는 상태에서 정보 5칸은 대부분 이탈 지점이다. 특히 "고민"을 꺼내러 온 사람에게 이메일부터 묻는 것은 문턱이 높다.
- [제안] **첫 대화는 가입 없이**(Firebase 익명 로그인 — 같은 Firebase Auth 안의 기능이라 App Check·AI Logic 구조는 그대로). 가입은 "이 질문을 보관하고 다른 기기에서도 보고 싶다"는 순간에 제안한다(익명 계정 → 이메일 계정 연결).
- 지키는 것: Gemini 전송 동의는 **첫 전송 전에 한 번 체크**로 그대로 받는다(삭제·약화 아님, 위치만 이동).

#### ② 시작 전에 16개 페르소나 중 하나를 골라야 한다
- [근거] 로그인 뒤 화면 = 페르소나 16개 카드 → 시작하기.
- [본성] 선택지가 많으면 고르는 일 자체가 피곤해지고 시작을 미룬다. 게다가 고민을 말하기 전에는 누가 맞는 상대인지 알 수 없다.
- [제안] **기본(내면 명탐정)으로 바로 시작**, 페르소나는 대화 중 언제든 바꾸기(v3.0 프롬프트에 이미 "페르소나 바꿔줘" 명령이 있음). 첫 화면에는 대표 3개만 보이고 "더 보기".

#### ③ 질문 카운터 [Q3/10]와 "10개 = 1회기"
- [근거] 사용 중인 v3.0 프롬프트 5장. 그런데 STATUS·정리 문서의 프로젝트 규칙은 "질문 횟수 강제 없음, 1~2턴 뒤에도 바로 답 듣기·정리·멈추기 가능"이다. **프로젝트 규칙과 라이브 프롬프트가 충돌한다.**
- [본성] 번호가 붙으면 대화가 시험·설문처럼 느껴진다. "아직 7개 남았네"가 되는 순간 사람은 대답을 줄이거나 떠난다.
- [제안] 화면과 답변에서 **카운터를 빼고**, 정리 시점은 "중요한 연결을 발견했을 때 / 같은 얘기가 맴돌 때 / 사용자가 원할 때"(v2.4 원본의 방식)로 되돌린다. 내부 참고값(5~7회)은 남겨도 보이지 않게.

#### ④ 라이브 프롬프트가 "마음 상담 탐정"·존댓말 상담형
- [근거] v3.0 제목 "마음 상담 탐정", "상담자처럼 듣고", "상담 기법". STATUS가 이미 "v3.0은 심리상담형·존댓말이라 프로젝트 기준(의료·상담 아님, C안 반말)과 충돌"로 결정 대기에 올려 둠.
- [본성] 사람은 "상담받는다"는 틀에 들어가면 환자 역할을 하게 되고, 스스로 발견하는 대신 답을 기다린다. 프로젝트 목표(스스로 질문 발견)와 반대 방향이다.
- [제안] 큰 틀 단계에서 **이 충돌을 먼저 결정**한다(§10 결정 1). 방향 제안: "상담" 단어를 빼고 "같이 생각 따라가 보기"로, 말투는 C안 기준. 안전 장(8장)은 한 글자도 줄이지 않는다.

#### ⑤ 빈 입력창 앞에서 "어떤 마음의 사건을 살펴볼까요?"
- [근거] 첫 응답 문구(v2.4·v3.0 공통). 승인 문구 '지금 고민이 뭐야?'도 빈칸 질문이다.
- [본성] 대부분은 정리된 고민을 들고 오지 않는다. "뭔가 찜찜한데 뭔지 모르겠다"가 보통이다. 빈칸은 "잘 써야 한다"는 부담을 만든다.
- [제안] 빈칸 옆에 **장면 3개를 고를 수 있게**: 책 초안의 장면을 그대로 쓴다(퇴근길 맥주 한 캔 / 알람 끄고 바로 휴대폰 / 화난 날 손이 먼저 나감). 고르면 "이런 비슷한 순간 있었어?"로 시작. 콘텐츠 ID로 책과도 바로 이어진다(예: TC-1-3-Q01).
- 승인 문구 '지금 고민이 뭐야?'와 탐색 A안은 그대로 두고, 장면 칩만 추가하는 제안이다.

#### ⑥ 대화가 저장되지 않아서, 찾은 질문이 창을 닫으면 사라진다
- [근거] index.html: "대화는 저장하지 않는다(페이지 메모리에만)". v3.0 프롬프트도 "이어가려면 보고서를 복사해 새 대화에 붙여 넣으라"고 안내.
- [본성] 사람은 자기가 만든 것, 가진 것을 아낀다. 애써 찾은 질문이 사라지면 다시 올 이유가 없다. "복사해서 붙여 넣기"는 거의 아무도 하지 않는다.
- [제안] **대화 전체가 아니라 "확정한 질문 한 줄"만 보관**(사용자가 확정 버튼을 눌렀을 때만). 프라이버시 원칙(기본 비공개, 저장과 공유 분리)과 맞고, 저장량도 아주 작다. → 이것이 메타보기 자동 카운팅(+3)의 유일한 근거 데이터가 된다(§7-C).

#### ⑦ 회기 보고서가 6항목으로 길다
- [근거] v3.0 6장: 사건 개요·단서·단서 노트·가설 2~3개·열린 질문·작은 실험 + 선택지 3개.
- [본성] 긴 보고서는 훑고 넘긴다. 사람에게 남는 건 한 문장이다.
- [제안] 보고서 첫 화면 = **"지금 내 질문" 후보 1개 + 근거 단서 2개 + [이게 맞아 / 고칠래]**. 나머지 항목은 접어 두기("자세히"). 확정은 사용자가 직접(프로젝트 규칙 그대로).

#### ⑧ "적기"에 기대는 설계
- [근거] 책 도입부("적기 시작했다"), 통합계획(경험·결과·자유·행복 신호 기록, 지식 카드), 신호 파트의 기록 흐름.
- [본성] 기록은 처음 며칠만 한다. 적는 게 숙제가 되면 앱을 피한다.
- [제안] **적지 않아도 쌓이게**: 대화 끝에 AI가 "오늘 나온 연결: 피곤함 → 맥주 → 머리는 그대로" 한 줄을 만들어 보여 주고, 사용자는 [맞아 / 고칠래 / 버려] 한 번만 누른다. 직접 쓰기는 선택.

#### ⑨ 5단계를 1단계부터 순서대로 통과하게 되는 구조
- [근거] 5단계는 "지도 순서"로 확정(바꾸지 않음). 현재 앱은 1단계(좋은 질문)만 있다.
- [본성] 사람은 문제나 바람을 들고 온다("술 좀 줄이고 싶어" = 4단계, "그냥 내 하루를 살고 싶어" = 5단계). 원하는 곳이 아닌 1단계부터 하라고 하면 "내 얘기를 안 듣는다"고 느낀다.
- [제안] **순서는 지도로 유지하고, 입구는 어디서나**. 사용자가 4단계 얘기로 들어와도 대화는 받아 주고, 엔진이 "그 바람 뒤에 있는 질문"으로 1단계에 자연스럽게 점을 찍는다. 맵에는 "지금 여기"만 표시. 단계를 잠그는 문(게이트)은 만들지 않는다.

#### ⑩ 신호 "분리" — "그 질문은 나와 다르다"를 인식시키기
- [근거] 정리 문서 1장: 2파트 = 신호와의 분리(근본 질문이 나와 다르다는 것을 인식) + 전환.
- [본성] 오래된 믿음을 "너와 다르다"고 정면으로 들으면 사람은 방어한다(자기 일부를 부정당하는 느낌). 설득할수록 버틴다.
- [제안] 구조(분리 → 전환)는 그대로 두고, **화면 경험은 "관찰"과 "실험"으로**: "그 신호가 올 때 몸은 어땠어?", "이번 주에 한 번만, 그 신호가 와도 10분 기다려 보면 어때?" — 분리는 사용자가 직접 깨닫는 결과이지, 앱이 말해 주는 문장이 아니다(설교 금지 규칙과도 같다). 문구는 모두 제안.

#### ⑪ 반복이 필요한데(신호 전환반복) 다시 올 계기가 없다
- [근거] 출석·연속 기록·일일 목표·알림 경쟁 금지(확정). 그런데 3·4단계는 반복이 핵심.
- [본성] 사람은 잊는다. 그렇다고 스트릭은 죄책감을 만든다(금지가 맞다).
- [제안] **사용자가 직접 정하는 "신호 순간" 약속 하나**: "편의점 앞에 서면 → 오늘 질문 한 줄 떠올리기". 앱이 시간마다 부르지 않고, 사용자가 원하면 그 순간 쓸 한 줄 카드만 홈 화면/위젯에 둔다. 횟수 표시 없음, 메타보기 변화 없음(규칙 그대로).

#### ⑫ 개발 방식 자체가 사람(사용자·AI 협업)의 본성에 거스르는 곳
- [근거] STATUS의 "결정 대기" 항목이 버전마다 10개 안팎씩 쌓임. 작은 수정 → 검토 → 실기기 → 또 수정 루프가 v3.3.9~v3.3.14로 이어짐(지시문 §1이 직접 인정). 화면 문구 하나가 6개 언어 × 승인으로 곱해짐.
- [본성] 결정이 쌓이면 사람은 결정을 미룬다. 전체가 안 보이면 눈앞의 작은 것만 고치게 된다. 범위가 넓으면 진척감이 사라진다.
- [제안]
  1. **결정 시트 1장**: 대기 결정을 "기본값 + 바꿀 때만 표시" 형태로 한 장에 모은다. 사용자는 기본값에 동의하면 아무것도 안 해도 된다.
  2. **걷는 뼈대(walking skeleton) 먼저**: 못생겨도 첫 화면→대화→확정→보관→맵→다음 파트 문→책 연결이 **끝까지 한 번 이어지는** 판을 먼저 만든다(§7-B 1단계).
  3. **다국어는 "함께 만든다"를 지키되 묶어서**: 화면 문구 키를 뼈대 단계마다 한 번 얼리고(freeze), 언 묶음만 6개 언어로 만든다. 매 수정마다 6개 언어를 고치지 않는다. (사용자 결정 2026-11-01 "나중으로 미루지 않는다"와 충돌하지 않게 단계별 동시 진행으로 제안. 결정 필요 → §10 결정 5)

### 7-B. 바뀐 개발 순서 (제안)

지금: 1파트 좋은질문 페이지를 다듬는 중(v3.3.9 → v3.3.13 → v3.3.14 보류).
제안: **5개 단계로, 앞 단계가 끝까지 이어진 뒤에만 다음 단계로.**

| 순서 | 이름 | 끝났다는 기준 | 다루는 본성 항목 |
|---|---|---|---|
| 0 | 결정 시트 | 사용자가 결정 1~6(§10)을 기본값 포함해 정함 | ③④⑫ |
| 1 | 걷는 뼈대 (1파트 전체 흐름) | 가입 없이 시작 → 장면 칩 또는 빈칸 → 대화(카운터 없음) → 질문 후보 1개 → 확정 → 질문 한 줄 보관 → 메타보기 53 → 5단계 맵 1단계에 점 → "2파트로" 문(빈 화면이어도 됨) → 책 장 연결(콘텐츠 ID) | ①②③⑤⑥⑦⑨ |
| 2 | 2파트 뼈대 (신호) | 보관된 질문에서 시작 → 관찰형 대화 → 연결 한 줄(상황→생각→행동) 확인 → 보관 → 맵 2·3단계 점 | ⑧⑩ |

### 7-C. 구조 제안 (코드 구조 큰 틀)

1. **대화 엔진 1개 + 파트 모듈 3개**: 파트마다 앱을 따로 만들지 않는다. v2.4 원본의 CORE / PERSONA / LOCALE / PRESENTATION 분리에 **PART 모듈(1·2·3파트별 지침 조각)**만 더한다. 안전 장은 CORE에 고정해 어느 파트에서도 같다.
2. **보관 데이터는 최소 3종**(통합계획 v3.2 데이터 모델의 축소판, 추가만):
   - `ConfirmedQuestion(id, text, created_at, content_id?)` — 사용자가 확정한 질문 한 줄
   - `SignalLink(id, question_id, situation, thought, action, created_at)` — 사용자가 [맞아]를 누른 연결 한 줄
   - `Experiment(id, signal_id, plan, cue?, result: helped|not|unsure|null)`
   - 대화 원문은 보관하지 않는다(현재 원칙 유지). 처음엔 기기 저장, 계정 연결 시 동기화.
3. **메타보기 자동 카운팅**: `50 + 3 × ConfirmedQuestion 개수`. 확정 버튼만이 점수를 바꾼다 → 활동 횟수·출석과 무관하다는 규칙이 데이터 구조로 보장된다(마인드맵 "미결 · 자동 카운팅" 해결 경로).
4. **맵 = 보관 데이터의 그림**: 5단계 맵은 따로 관리하는 상태가 아니라 위 3종 데이터를 그린 것. 단계 잠금 없음.

### 바꾸지 않은 것

- 3파트·5단계 순서·파트≠단계 구분, 버전 분리(일반 버전 제작), 콘텐츠 ID·딥링크, 메타보기 규칙(50/+3/보상 제외), 6개 언어 동시 제작 원칙, 안전 문구 전부(위기 시 멈춤·응급번호 단정 금지 포함), 용어 '신호 전환반복', 승인 문구('지금 고민이 뭐야?', 탐색 A안, 첫 화면 C안), 움직임 기본값 still, 비밀 키 원칙, 보류 항목(v3.3.14 등)은 보류 그대로.

## 8. 확인한 것

- 모의·실기기 확인 없음. 이 작업은 **문서 분석**이다.
- 문서 대조로 확인한 사실:
  - 라이브 v3.0 프롬프트에 `[Q n/10]`, "질문 10개 = 1회기"가 있다 ↔ 프로젝트 규칙 "질문 횟수 강제 없음"(STATUS v3.3.2·v3.3.4, 정리 문서 4장)과 충돌.
  - 라이브 v3.0 프롬프트 제목·역할에 "상담"이 들어 있다 ↔ 고정 기준 "의료·상담 서비스 아님"과 표현상 충돌(STATUS가 이미 결정 대기로 기록).
  - 라이브 페이지는 대화를 저장하지 않으며, 로그인 없이는 대화할 수 없다.
  - 페르소나 16개를 시작 전에 고르게 되어 있다.

## 9. 확인하지 못한 것

- 바탕 파일들의 해시·바이트(작업 환경에서 raw 내려받기 불가, §5).
- index.html 마지막 약 6,300자.
- Firebase 익명 로그인이 현재 프로젝트 콘솔에서 켜져 있는지, App Check·AI Logic과 함께 무료(Spark)로 문제없는지 — **가설**, 콘솔 확인 필요.
- 위 본성 판단(이탈 지점 등)은 일반적으로 알려진 행동 경향에 근거한 **가설**이고, 이 앱 사용자로 측정한 것이 아니다. 뼈대가 서면 사용자 1~3명에게 실제로 써 보게 하는 것이 확인 방법이다.
- staging의 v3.3.2 LITE·v3.3.4 프로토타입(5단계 맵 데모 등)은 이번에 읽지 않았다. 2단계 뼈대 작업 때 읽어야 한다.
