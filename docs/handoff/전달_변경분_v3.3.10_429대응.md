## 1. 원인 분석 (사실 / 계산 / 가설 구분)

### 1-1. 공식 문서로 확인한 사실

- Firebase AI Logic의 Gemini 한도는 **프로젝트 단위**이고, 그 프로젝트를 쓰는 모든 앱·IP가 나눠 쓴다. 한도를 넘거나 모델 용량이 모자라면 **429**를 돌려준다. 사용자당 한도는 기본 **분당 100건**이다. (Firebase AI Logic "Rate limits and quotas", 2026-10-27 갱신)
- Gemini API 한도는 "API 키가 아니라 프로젝트 단위"로 걸리고, **하루 한도(RPD)는 미국 태평양 시간 자정에 초기화**된다. 무료 등급 모델별 숫자는 문서에 없고 AI Studio의 Rate limit 화면에서 보라고 한다. (Gemini API "Rate limits", 2026-10-26 갱신)
- `gemini-3.8-flash`는 2026-09-02 출시된 정식(Stable) 모델이고, Gemini Developer API로 쓸 때 Blaze가 필요 없는 모델로 표시돼 있다. `gemini-3.5-flash-lite`, `gemini-3.1-flash-lite`도 같다. (Firebase AI Logic "Supported models")
- 2026-11-02부터 AI Logic에 App Check 적용이 필수다. (Firebase AI Logic "Pricing", 2026-10-27 갱신)

### 1-2. 공식 문서가 아닌 보고 (참고만, 단정 금지)

- Google 개발자 포럼 글(2026-10-15, 한 사용자의 대시보드 화면): **Gemini 3.8 Flash 무료 등급 RPM 5 · TPM 250K · RPD 20**.
- scriptbyai 기사(2026-10-19, AI Studio 표를 출처로 밝힘): 3.8 Flash **5 / 250,000 / 20**, 3.5 Flash-Lite·3.1 Flash-Lite **10 / 250,000 / 500**.
- 두 출처가 같은 숫자지만 공식 문서가 아니다. **이 프로젝트(`thought-connection`)의 실제 값은 사용자가 AI Studio에서 확인해야 한다.**

### 1-3. 계산 (코드와 파일에서 직접 잰 값)

- 매 요청 지침(systemInstruction) = v3.0 프롬프트 9,249자(UTF-8 19,902바이트) + 앱 실행 정보 298자(655바이트) = **20,557바이트**.
- 토큰 상한 추정: 토큰 하나가 최소 1바이트를 덮는다고 보면, 요청당 지침은 **20,557토큰 이하**다. (가정: Gemini 토크나이저 명세로는 확인하지 못함. 실제 값은 v3.3.10이 콘솔에 남기는 `prompt` 숫자로 확인)
- 짧은 대화(기록 3,000바이트 이하)라면 요청당 23,697토큰 이하 → RPM 5로 1분에 최대 5건 = **118,485토큰 이하 < TPM 250,000**. 즉 **짧은 대화에서는 토큰 한도보다 요청 수 한도(RPM·RPD)에 먼저 걸린다.** 토큰 한도에 먼저 걸리려면 요청당 50,000토큰(=250,000÷5)이 넘어야 하고, 이는 대화 기록이 아주 길 때만 생긴다(MAX_CHARS 120,000자 = 한글 기준 최대 약 360,000바이트).
- 1회기 요청 수(코드 구조): 시작 1건(`begin()`이 자동으로 보냄) + 답 10건 = **11건**. 실패 후 '다시 보내기'·'새로 시작'도 1건씩이다.
  - RPD 20이라면: 20 ÷ 11 = **1.82 → 프로젝트 전체(모든 사용자 합계)로 하루 1회기 남짓**.
  - RPD 500이라면(Flash-Lite 보고값): 500 ÷ 11 = **45.5회기**.
- 첫 테스트 시각 2026-11-02 06:27(대만) = 2026-11-01 14:27(태평양 표준시). 다음 하루 한도 초기화는 **2026-11-02 16:00(대만 시간)**. (11월 1일에 미국 서머타임이 끝나 태평양 시간 = UTC−8. 브라우저 Intl로 계산·점검함)

### 1-4. 가설 판단 (확인 전까지 가설)

| 지시문 가설 | 판단 | 근거 |
|---|---|---|
| 1 분당 한도(RPM) | 가능. 단 8건이 1분 넘게 걸쳐 모두 실패했다면 RPM만으로는 설명이 안 된다 | RPM은 1분 단위 |
| 2 하루 한도(RPD) | **가장 유력한 후보 중 하나**. RPD가 20이라면 시작·재시도·새로 시작만으로도 빨리 닳는다 | 1-2, 1-3 |
| 3 토큰 한도(TPM) | 이번 짧은 테스트에서는 **가능성 낮음** | 1-3 계산 |
| 4 모델·요금제 한도 | 숫자 미확인. 추가로 **'한도 0'**(그 모델의 무료 몫이 0) 가능성도 있다. 이 경우 첫 요청부터 실패하고 기다려도 안 풀린다 | dev.to 글(2026-10-16): `limit: 0`은 기다려도 같은 오류 |
| 5 설정 오류(App Check 등) | 제외 | 코드상 429와 401·403은 다른 문구 |
| (추가) 모델 혼잡 | 가능. Firebase 문서상 모델 용량 부족도 429 | 1-1 |

**어느 것인지 가르는 열쇠:** 429 응답 본문에 Google이 원인 정보(quotaId: `…PerMinute…` / `…PerDay…`, 한도 값, 재시도 대기 시간)를 넣어 보낸다. v3.3.9는 이 정보를 버리고 한 가지 문구만 보여 줬다. v3.3.10은 이를 읽어 화면의 '자세히'와 개발자 콘솔에 보여 준다. 단, Firebase AI Logic 중계가 이 정보를 그대로 넘기는지는 실제 429로 확인하지 못했다.

## 3. 확인한 방법

- **가짜 응답 점검(실제 모델 아님):** 로컬 Chromium + `window.__TC_BACKEND` 가짜 서버로, Gemini 429 응답 형식을 흉내 낸 오류를 넣어 31개 항목 점검 → **31/31 통과**. 항목: 시작 1건, 토큰 콘솔 기록, 분당 한도 안내·원인 표시·대기 중 요청 0건·글 유지·버튼 잠금·대기 끝 다시 보내기, 사용자 차례 합치기, 하루 한도 시각(대만 오후 4:00) 표시·보관·새로고침 뒤 요청 0건·영어 전환, 한도 0, 원인 없는 429(60초), 403+quota 글자 → 설정 안내, 401 → 설정 안내, 바쁠 때 Enter 글 유지, 스크립트 오류 0, 태평양 자정 계산 5건(서머타임 시작·끝 포함).
- 휴대폰 폭(390px)·데스크톱(1280px) 화면 확인: 가로 넘침 없음, 안전 안내 줄 그대로 보임.
- SDK 동작 근거: GitHub `firebase/firebase-js-sdk` 태그 `firebase@13.0.0`(= `@firebase/ai@3.0.0`)의 `packages/ai/src/requests/request.ts`(오류 글에 `[상태] 메시지 + details JSON`을 넣고 `customErrorData.status`·`errorDetails`를 채움), `stream-reader.ts`(합친 응답에 usageMetadata 없음), `chat-session-helpers.ts`(차례 규칙).

## 4. 확인하지 못한 것

- **실제 Gemini 연결 점검 전부.** 이 작업 환경에서는 Google 서버에 요청을 보낼 수 없고, 사용자 프로젝트에 계정을 만들어 시험하지 않았다.
- `thought-connection` 프로젝트의 실제 RPM·TPM·RPD 값과 오늘 사용량.
- Firebase AI Logic 중계가 429에 원인 정보(QuotaFailure·RetryInfo)를 붙여 보내는지. 안 붙이면 v3.3.10은 '알 수 없음(60초)'으로 처리한다.
- 429로 거절된 요청이 하루 한도에 포함되는지.
- 첫 테스트에서 **대화 시작 직후 AI 첫 인사가 나왔는지**(스크린샷을 직접 보지 못함). 첫 인사도 실패했다면 '하루 한도 소진' 또는 '한도 0' 쪽, 첫 인사는 나왔다면 '분당·하루 한도' 쪽으로 좁혀진다.
- Gemini 유료 등급의 단가, 무료·유료의 데이터 사용 차이(Gemini 요금 페이지를 이번에 열지 못함 — v3.3.9 문서의 기존 서술만 있음).
- 새 문구 5개 언어(en, es-419, hi, zh-TW, ja)의 자연스러움 — **원어민 검토 대기, 특히 힌디어**.

## 5. 사용자가 지금 확인해 줄 것 (코드 없이)

1. **AI Studio → Rate limit 화면**(aistudio.google.com/rate-limit, Gemini API 문서가 안내하는 곳)에서 프로젝트 `thought-connection`의 `gemini-3.8-flash` 무료 등급 RPM·TPM·RPD와 오늘 사용량. (Firebase 프로젝트가 그 화면 목록에 바로 보이는지는 확인하지 못했다)
2. **Google Cloud 콘솔 → Gemini Developer API(표시 이름 Generative Language API) → 관리 → 측정항목**: 응답 코드별 트래픽에 429가 몇 건인지. 같은 화면의 **할당량** 탭에서 한도 값.
3. **Firebase 콘솔 → AI Logic → AI monitoring 탭**: 요청 수·오류 수.
4. **대만 시간 오늘 16:00 이후**, 공개 페이지에서 대화를 시작해 **딱 1건만** 보내 보기.
   - 성공 → 하루 한도 소진이 원인이었을 가능성이 크다.
   - 바로 실패 → 한도 0 또는 다른 원인. v3.3.10을 올린 뒤라면 '자세히'에 원인 이름이 보인다.
